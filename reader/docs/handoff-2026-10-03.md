## 3. NPU / QNN — a helyzet 2026-10-03-án

### 3.1 Amit az EP elutasít

`onnxruntime-qnn` 2.5.0 a `foundry-dev` venvben működik, explicit regisztráció kell:

```python
import onnxruntime as ort, onnxruntime_qnn as qnn_ep
ort.register_execution_provider_library(qnn_ep.get_ep_name(), qnn_ep.get_library_path())
devices = [d for d in ort.get_ep_devices() if d.ep_name == "QNNExecutionProvider"]
so = ort.SessionOptions()
so.add_provider_for_devices(devices, {"backend_type": "htp"})
sess = ort.InferenceSession(path, so)   # NEM providers=[...] — az visszairányít CPU-ra
```

- `vocoder.onnx` → a session létrejön és a provider-lista QNN-t mutat, de
  **nem gyorsít** (RTF 0,3317 vs 0,3383) — a 2026-10-04-i vizsgálat szerint
  ennek az az oka, hogy **az EP itt sem az NPU-n fut, hanem CPU-n** (lásd 3.3)
- `vector_estimator.onnx` → `EP_FAIL: Dynamic shape is not supported yet, for input: total_step`
- Statikusra vágott ONNX (bemenetek `dim_value`-ra cserélve) → belső `Tile` node
  futásidőben számított `repeats` miatt nem tölthető (1198 → 138 dinamikus tenzor)

## 5. Amit NEM szabad elrontani

| Tanulság | Miért |
|---|---|
| RTF-mérés előtt **töröld a mérendő cache-bejegyzést** | a `generate()` gyorsítótáraz, különben 0 s-t mérsz (a `scripts/bench_supertonic_variants.py` asserttel védi) |
| `settings.save()` a motor **felépítése előtt** | különben a `folder`/`variant` a régi értéket olvassa |
| `PeakWorkingSetSize` monoton nő | **külön processz kell** variánsonként a memóriaméréshez |
| A WER-méréshez **melegítő szöveg ne legyen** a korpusz egyik mondata | különben az első mondat gyorsítótárazott lesz |
| **A VITS/Piper hullámát két futás között ne hasonlítsd össze** | a generátor random zajt kap (`noise_scale=0,667`), két hívás szándékosan különbözik — a korreláció ≈ 0,15. Csak `scales=[0,1,0]` mellett érvényes az emulált/natív összevetés |
| **Gated HF-repónál a `model_info()` siker nem jelent hozzáférést** | a `pltobing/XTTSv2-Streaming-ONNX`-nál a metaadatok látszanak, a fájlletöltés 403-at dob; a mérvadó próba a `hf_hub_download`/`snapshot_download` |
| Hang kiválasztásához a `voice:` token **a karakterlánc elején** kell | `"[voice:M3]"` csendben az alapértelmezett hangra esik vissza; ez két hang helyett ugyanazt mérné kétszer |
| **x86_64 emuláció gyorsabb a natív ARM64-nál** | az x86_64 PyTorch CPU-build jobban optimalizált (mérve 2,6× az F5-TTS-nél); ne a natív ARM64 venv legyen az első választás |
| ASR-mérésnél a `transcribe()` **dictet** ad vissza | `{"text", "words"}` — ha a dictet adod át a `score_transcript`-nek, a teljes nyers szó-időzített kimenetet számolja át, és hamis ~8 % WER-t kapsz |
| A hangfeldolgozás RTF-je **idő/hang**, nem hang/idő | a Supertic mérés RTF 0,144 = *gyorsabb*; ha egy klónozónál 0,04-et látsz, az 25× lassabb, nem gyors |
| A fixture szerver **ugyanaz a port** nem lehet nyitva | Windowson két példány is figyel egy porton, és a régi kódot szolgálja ki |
| **A QNN EP `get_providers()` listája nem bizonyít NPU-futtatást** | ezen a gépen az EP csendben CPU-ra esik, mégis QNN-t mutat; a profil `provider` mezőjét kell nézni (`scripts/npu_probe.py`) |
